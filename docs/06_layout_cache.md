# Практики 8–10. Адаптивность и кэш

Фиксированная вёрстка задаёт постоянные размеры. Резиновая использует относительные размеры и свободное пространство. Отзывчивая сочетает гибкие размеры с медиазапросами; адаптивная может переключать отдельные варианты расположения. В приложении максимальная ширина 900 px, гибкие поля и медиазапрос при 600 px.

Проверка выполнена в Chrome через DevTools Protocol: `Emulation.setDeviceMetricsOverride`. Размеры заданы в CSS-пикселях, DPR=1, мобильный режим включён для ширины меньше 600. Скрипт: `scripts/collect_evidence.py`. На страницу добавлены обычное и предельное название из 80 букв без пробелов.

| Viewport | Причина выбора | После исправления |
|---|---|---|
| 320×568 | Минимальный узкий экран | PASS |
| 375×812 | Типовой узкий смартфон | PASS |
| 768×1024 | Планшет | PASS |
| 1280×720 | Небольшой ноутбук | PASS |
| 1920×1080 | Настольный монитор | PASS |

Измерялись `innerWidth` и `document.documentElement.scrollWidth`; второе значение не должно превышать первое. На всех пяти размерах после исправления условие выполнено. До исправления обнаружен [BUG-02](02_bugs.md).

## Кэш и конфигурация

В DevTools отключён сетевой кэш через `Network.setCacheDisabled`; выполнено обновление страницы. Задачи текущей сессии остались. Для `/api/health` получены HTTP 200 и `Cache-Control: no-store`; эти значения записаны в `inspection.json`. Сервер отдаёт такой заголовок и для статических файлов, поэтому во время учебных проверок используется свежая версия ресурсов.

Для повторения сбоя сначала проверить адрес/порт, версию браузера, наличие cookie, версию JavaScript, viewport, кэш и тестовые данные. Новый WebDriver создаёт отдельный профиль; состояние предыдущего теста не должно использоваться. Очистка cookie разрывает связь с сессией, очистка сетевого кэша сама по себе не удаляет задачи сервера. Остановка сервера удаляет все данные в памяти.
