# Практики 18–21. План регрессии

Новая версия: исправлены синтаксическая ошибка JavaScript и перенос длинного названия задачи. Риски: потеря входа, обработчики кнопок, отображение предельных названий, совместимость браузеров.

| Этап | Виды и уровень | Проверки |
|---|---|---|
| 1. До запуска | Статическое, белый ящик | `node --check`, просмотр обработчиков и границ в сервере |
| 2. API | Функциональное, интеграционное, серый ящик | Коды, границы, авторизация, изоляция сессий |
| 3. Сборка | Автоматизированное системное smoke, чёрный ящик | Пять основных сценариев Selenium |
| 4. Регрессия | Расширенное функциональное | Неверные данные, пустые поля, текст вместо HTML, iframe, вкладки |
| 5. Представление | Нефункциональное, совместимость и UI | Пять размеров, длинный текст, Chrome и Firefox |
| 6. Исследование | Сценарное/исследовательское | Длинная строка, повторное обновление, подмена состояния API в Charles |
| 7. Приёмка | Подтверждение исправлений | Сопоставить BUG-01/02, JUnit, снимки, состояние CI |

Ручная проверка полезна для визуальных ошибок и изучения нового интерфейса. Автоматическая — для повторяемых сценариев с ясным результатом. Вход, задачи и валидация относятся к функциональности; адаптивность, доступность, производительность — к нефункциональным свойствам. Отдельное нагрузочное тестирование в комплекте не проводилось.

Компонентная проверка охватывает отдельную функцию; интеграционная — границу клиент/API или обработчика/хранилища; системная — весь путь пользователя в браузере. Серый ящик использует знания о сессиях/API, белый — код, чёрный — только входы и выходы. Изолированных unit-тестов здесь нет; API-тесты проходят через настоящий HTTP-сервер.

Смоук — короткая проверка работоспособности. Регрессия — поиск последствий изменений. Перепроверка дефекта проверяет конкретное исправление. Расширенный набор добавляет негативные и граничные сценарии. Исчерпывающее тестирование всех строк, браузеров и состояний невозможно; используются классы эквивалентности и границы.

Порядок: новая изолированная сессия → smoke → негативные/API → вёрстка → второй браузер. При падении сохранить JUnit, снимок и исходную страницу, выяснить причину, исправить приложение или тест, повторить затронутые проверки и полный набор после значимого изменения.

Критерий завершения: все обязательные тесты пройдены, исправления перепроверены, журнал и снимки сохранены, CI завершён успешно. Неиспытанные реальные устройства не считаются пройденными. Для дальнейшей версии запланированы Safari, Windows, отмена удаления и восстановление после сетевой ошибки; результаты для них пока не заявлены.
