## Подготовка и изоляция

Python-сервер без внешней БД. Фикстура запускает его на свободном loopback-порту. Каждый UI-тест получает новый WebDriver и новую cookie-сессию. Тестовые данные: `student@example.com` / `Study123!`, задачи с названиями из сценариев. Реальные данные не используются. API-тесты создают независимые CookieJar. После теста браузер закрывается; после сессии pytest сервер останавливается. При внешнем `BASE_URL` сервером управляет запускающий.

## Настройка CI

`.github/workflows/tests.yml` запускается на push, pull_request и вручную. Только изменения README, docs и evidence не вызывают новый прогон. Две матричные job выполняют pytest в Chrome и Firefox; отдельная job запускает сервер и Puppeteer. `upload-artifact` с `if: always()` сохраняет отчёты и снимки даже при падении. Внешние сервисы и секреты для приложения не нужны.

## Анализ падений

Первый локальный прогон выявил BUG-01. Синтаксическая ошибка мешала выполнению JavaScript, поэтому падали и другие зависящие от входа тесты. Это один дефект приложения с несколькими последствиями, а не десять отдельных багов.

В [первом CI](https://github.com/unw1b3s/testing/actions/runs/40562010031) Chrome и Puppeteer прошли, Firefox дал 24 PASS / 5 FAIL. Причина в коде теста: `hasattr(driver, 'execute_cdp_cmd')` возвращал true для Firefox, хотя браузер не поддерживает CDP. Условие заменено проверкой `browserName`; Firefox меняет размер через WebDriver. Это ошибка тестового кода. [Исходный журнал](../evidence/ci/firefox-initial.log). После исправления CI №2 прошёл во всех job. Неподтверждённых «случайных» падений не заявлено.

Поддержка: при смене интерфейса обновлять локаторы POM; после изменения требований — данные и ОР; при обновлении браузеров — проверить драйверы и сохранить версии. Упавшую проверку не отключать до выяснения причины.
